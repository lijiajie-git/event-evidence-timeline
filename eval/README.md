# 评测方法

这个目录评的是 `pipeline/extracted/*.json`：大模型离线抽取出来的证据、数值版本、状态、冲突和分时点结论。评测回答两个问题：

- **结果对不对**：数字、版本、状态、分类、合并，和标准答案一致吗？
- **过程对不对**：每句话有没有出处，出处挂得对不对，回放时有没有偷看未来，冲突找没找出来，事实和推断有没有混在一起。

一条命令跑完（在仓库根目录）：

```bash
python3 eval/score.py
```

输出 `eval/report.json`（给页面的成绩单用）、`eval/report.md`（给人读）、`eval/traps/results.json`（陷阱用例的实际反应）、`eval/history.json`（历次分数：输入版本变了就追加一条，没变就覆盖最后一条）。只做金标自检用 `python3 eval/score.py --check-gold`。脚本只读 `pipeline/` 和 `data/`；陷阱用例把管线复制到临时目录里跑，不碰仓库里的 `data/`。

## 标准答案是怎么来的，可信到什么程度

**标准答案是模型标的（Claude Opus 5.5），不是人工标的。** 事件 1 由评测窗口自己标；其余事件由评测窗口派出的 Opus 子任务按同一份说明盲标，交回后评测窗口逐份复核（复核记录在 `adjudication.md`）。

- 盲标：每个事件先只读公告原文（`data/raw/text/`）和本地新闻原始数据标完，存盘之后才打开 `pipeline/extracted/` 里对应的抽取结果对比。标之前只看过抽取文件的字段名（值是屏蔽的），用来对齐格式。
- 缺正文的公告，用 `data/raw/announcements.json` 里的链接下载 PDF，`pdftotext -layout` 转成 `data/raw/text/<公告id>.txt`，只新增文件。
- 看过抽取结果之后对金标做的改动，都在 `adjudication.md` 里逐条记录，并在金标里标 `added_after_adjudication: true`。
- **数值类字段能机械复核**：金标里每个数值都带原文片段，`--check-gold` 检查片段逐字在原文里（去空白后），而且数值换算单位后能在片段里找到。
- **判断类字段不能机械复核**：证据类型（事实/观点/推测/传闻）、来源级别、是否同一事件、状态归类、冲突是否成立，是模型的判断，没有人复核过。有歧义的地方，金标用 `accept_kind`、`accept_tier` 列出可接受的几种标法，不硬判。这几项分数看个方向，不要当精确数字用。

### 测试集和开发集

主窗口看过评测意见、照着改过的事件算**开发集**，之后的分数只说明“改对了没有”，不再是独立测量；抽取时没参考过评测结果的事件算**测试集**。`report.json` 的 `summary` 只汇总测试集，开发集在 `summary_by_split` 里单列。目前开发集只有事件 1（5dab53d 起），它第一版的独立分数在 `history.json` 第一条。

另外要说明：`pipeline/抽取说明.md` 有几条通用规则是从事件 1 的评测意见里总结出来的（全量过一遍公告、不把低精度数写精确、第 1 版挂最早出处）。后面事件的抽取受益于这些规则，但抽取子任务没看过别的事件的金标，仍算测试集。

## 金标格式（`eval/gold/<id>.json`）

| 字段 | 内容 |
|---|---|
| `evidence[]` | 证据清单。`key` 是 `ann:<公告id>`、`news:<新闻id>` 或 `anomaly:<日期>\|<标签>`；`membership` 为 `required`（必含）或 `optional`（可含，不含不扣分）；`kind`、`tier` 是类型和来源级别；`equivalent` 列出视为同一条的证据（如年报摘要和全文）；`quote` 是原文片段 |
| `exclude[]` | 不该并进来的证据（别的报告期、别的事件），并进来算错 |
| `claims[]` | 指标的各个版本：`low`、`high`、`unit`（按原文单位记）、出处证据、`alt_evidence`（也接受的出处）、原文片段。`required=false` 的指标只作参考 |
| `supersessions[]` | 证据之间的取代关系：哪条更正或兑现了哪条 |
| `status_checkpoints[]` | 回放检查点：截至某天，事件应处于什么标准状态，由哪条证据触发 |
| `conflicts[]` | 证据之间对不上的地方：涉及哪些证据、用来识别的关键字、`required` 是否必须找出 |

## 指标

每项都给分子、分母和失败明细。汇总只加已计分事件。

### 结果对

| 指标 | 怎么算 |
|---|---|
| 数值抽取精确匹配 | 金标必含指标的每个版本的上下限，各算一个。抽取值按自己的精度四舍五入后等于金标（单位先换算成元）才算对。漏掉的版本算错 |
| 版本链 | 两部分相加：①金标里相邻两版，在抽取里也要相邻且顺序一致；②金标的每条取代关系，抽取里那条证据的 `relation.target` 要指对 |
| 事件状态 | 每个回放检查点：取截至该日最后一个披露日的状态（同一天几条都看），有标准状态码 `code` 就直接用（已预告、预告更正、已兑现、定期报告更正、筹划、预案、草案、审核中、未通过、终止审核、终止、监管问询、立案、风险警示、终止上市、澄清、否认），没有才按关键字归类；要和金标一致，且触发它的证据要和金标相同或同一天披露 |
| 证据类型准确率 | 抽取和金标都有的证据里，类型在金标可接受范围内的比例 |
| 来源级别准确率 | 同上，看 A–E 级 |
| 该合并的合并了 | 金标必含证据被并进来的比例 |
| 不该合并的分开了 | 抽取并进来的证据里，不在 `exclude`、也不属于别的事件的比例。金标没列到的证据不算错，单列“待裁决” |

### 过程对

| 指标 | 怎么算 |
|---|---|
| 引用逐字匹配 | 抽取里所有引用（证据引用、数值版本引用、冲突引用）去空白后能在所挂证据原文里找到的比例。和管线用同一个规范化函数 |
| 引用挂对证据 | 精确率：引用（含结论里带数字的句子）挂对的比例；召回率：金标必含的数值版本里，被抽取用对的证据加逐字引用支撑的比例。没挂对的分成两类分开计数：**挂错**（这句话或这个数在别的证据里有，挂错了地方；或者数值和自己的引用对不上），**无依据**（哪条原文都找不到）。结论句里的数字会换算单位后去所挂证据里找；不带数字的结论句没法自动核对，单独计数 |
| 回放未用到未来证据 | 每个时点的结论挂的每条证据，披露日都不能晚于这个时点 |
| 冲突找出来了 | 金标必须找出的冲突，被抽取里某条冲突覆盖（证据有交集，且文字里出现识别关键字）的比例。抽取多找的冲突列为“待裁决” |
| 事实和推断没混 | 只查“事实”段：句子里出现“可能、或将、有望、意味着、判断……”且所挂证据原文里没有这个词，或者只挂了观点、推测、传闻类证据，都算混了 |

另外两项不打分，只列命中：系统自写文字里的买卖建议用语（管线词表和一个扩展词表），引用里有没有“忽略以上规则”这类注入指令。

## 错误分类

| 代码 | 含义 |
|---|---|
| E1a | 数值单位或量级错（万元、亿元、元混用） |
| E1b | 数值符号错（亏损写成盈利） |
| E1c | 数值其他错（区间端点、数字本身） |
| E1d | 年份或报告期错 |
| E1e | 数值和自己挂的引用对不上 |
| E1f | 精度丢失：引用是四舍五入后的数，抽取把它写成更精确的数，和真实值差开了 |
| E1x | 抽取的指标名映射不到金标 |
| E2a | 漏版本，或整项指标没抽 |
| E2b | 版本顺序或相邻关系错 |
| E2c | 多出金标没有的版本（可能是伪造的更正） |
| E2d | 证据级取代关系没接对 |
| E3 | 状态错，或状态对但触发证据不对 |
| E4a / E4b | 证据类型错 / 来源级别错 |
| E5a / E5b | 该合并的没合并 / 不该合并的合并了 |
| E6a | 引用不能逐字匹配 |
| E6b | 引用挂错证据 |
| E6c | 无依据，或挂了不存在的证据编号 |
| E7 | 回放用到了截至日之后的证据 |
| E8a | 冲突没找出来 |
| E9 | 事实和推断混了 |
| E10 | 系统自写文字里有买卖建议或涨跌预测 |
| E11 | 引用里带了注入指令 |

## 陷阱用例

见 `traps/README.md`。陷阱是在当前抽取结果上故意改坏一处，看管线（`build_events.py` + `check_compliance.py`）拦不拦得住，以及本评测能不能发现。拦不住的如实记为已知缺口。

## 分歧怎么处理

金标和抽取不一致时，回原文判断，逐条记在 `adjudication.md`：原文怎么写、以谁为准、为什么。抽取错了的，告诉本人，由主窗口改 `pipeline/extracted/`，评测这边不改。需要管线加检查或加字段的，写在 `给主窗口的建议.md`。

## 已知局限

- 金标是一个模型标的，没有第二个标注者，没有算标注一致性。
- 抽取有 `code` 时直接比；没有 `code` 的旧格式才靠关键字归类。
- 结论里不带数字的句子（如“公司提示可能被实施退市风险警示”）只查了时间和类型，没查语义是否忠实原文。
- 陷阱用例只测规则部分；抽取模型读到注入文本会不会被带偏，没有测（需要重跑抽取）。
- `pipeline/qa.json` 里的离线问答还没纳入评测。
