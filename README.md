题目：投资事件情报与证据时间线。

- 仓库：https://github.com/lijiajie-git/event-evidence-timeline
- AI 使用与验证记录：[docs/AI使用与验证记录.md](docs/AI使用与验证记录.md)
- 测试说明：[docs/测试说明.md](docs/测试说明.md)

状态（2026-11-11）：数据管线和第一条完整事件已上线，页面是先上线的简版，正式界面和另外两条事件在做，会直接更新到这个仓库和同一个地址。

## 解决什么问题

一家公司的同一件事，会在几个月里被公告、快讯、评论、研报反复说，数字还会被公司自己改。看到其中一条消息的人很难知道：这事最早是谁说的，后来改过什么，现在算数的是哪一版。

以仓库里的第一条事件为例：\*ST国中 2025 年业绩预告，1-30 首次披露归母净利润亏损 1.04 亿至 1.30 亿元、扣非净利润为正；4-18 第一次更正，扣非转负；4-29 第二次更正，亏损扩大到 2.15 亿元；4-30 年报兑现并被实施退市风险警示；5-06 公司又更正了 4-29 那份更正公告里的一个持股比例。只看任何一条，都会得到不完整甚至过时的结论。

## 给谁用

- 关注个股的个人投资者：看到一条消息，想知道它是不是最新的、有没有被改过。
- 替客户盯事件的投顾助理：要给客户讲清楚一件事的来龙去脉，每句话都要有出处。

不做的：不预测涨跌，不给买卖建议，不做全市场实时监控，不做登录和推送。

## 核心设计

1. **事件合并**：先按"股票代码 + 事件类型 + 报告期或交易标的"用规则分桶，再由大模型判断是否同一件事，并写出合并理由。合并理由显示在页面上，可以被人检查。
2. **证据分类和权重**：每条证据标成事实、观点、推测、传闻四类之一。来源分五级（A 公司公告和交易所文件，B 媒体对公告的转述，C 媒体评论和研报观点，D 推测性报道和算法归因，E 传闻），权重由规则给定，不让模型打分。低级别来源不能推翻高级别来源。
3. **四种时间分开记**：发生时间（说法所指的日期或报告期）、披露时间（公告披露日或媒体发布时间，注明精度）、抓取时间、更新时间（数据源目前不提供，页面如实写"来源未提供"）。
4. **版本而不是覆盖**：被更正的数字不删除，保留为"前值"并注明被哪条证据在哪天取代。页面可以选"截至某天"，回放当时的结论。
5. **冲突单列**：证据之间对不上的地方单独列出，写明怎么处理、是公司更正的还是系统推断的。
6. **结论分三段**：事实、推断、还不确定。每句话挂证据编号，点一下跳到证据和原文片段。
7. **引用逐字校验**：模型给出的每条引用，必须能在公告正文或新闻摘要里逐字匹配到；匹配不到就拒绝生成数据文件。结论也不能引用"截至日"之后才出现的证据。

## AI 的角色

| 环节 | 谁做 | 说明 |
|---|---|---|
| 抓取、分桶、权重、状态、时间、行情片段 | 规则 | `pipeline/fetch*.py`、`pipeline/build_events.py` |
| 判断是否同一事件、写合并理由 | 大模型 | 输出在 `pipeline/extracted/*.json` |
| 从公告和报道里抽说法、数字、类型、关系 | 大模型 | 同上，每条带原文引用 |
| 写分时点结论，区分事实、推断、不确定 | 大模型 | 同上，每句带证据编号 |
| 校验引用、校验时序、合规词检查 | 规则 | 不通过就不生成 `data/events.json` |

为什么需要大模型：公告是长文本，更正公告要读懂"更正前、更正后、原因"；媒体标题里的问号、"或""有望"这类措辞决定它是事实还是推测；"审核未通过"和"交易终止"是两个不同状态。这些靠关键词规则做不准。为什么不全交给大模型：权重、状态和时间如果让模型自由发挥，结果不可复现，也没法审计。

**为什么不在网页上实时调大模型**：网页托管在 GitHub Pages，是纯静态站，没有地方安全存放模型密钥。所以大模型在本地离线跑，结果经校验后写进 `data/events.json`，网页只读这份文件。

## 数据来源

| 数据 | 来源 | 用途 |
|---|---|---|
| 公告元数据和正文 | 巨潮资讯网（法定信息披露平台）公开接口 | 事实类证据、数字的各个版本 |
| 个股新闻、异动解读 | 扶摇金融数据 API（`/api/news/stock/timeline-list`、`/api/news/anomaly/analysis`） | 转述、观点、推测类证据，媒体发布时间 |
| 日 K 线 | 扶摇金融数据 API（`/api/a-share/prices/historical`，不复权） | 各次披露前后的价格和成交额 |

仓库里只放页面用到的部分：新闻只留标题、来源、时间、链接和一句引用；行情只留每次披露前后 3 个交易日。原始抓取结果不入库。iFinD MCP 没有接入。

## 怎么跑

网页不需要构建，直接看在线地址；本地看用任意静态服务器：

```bash
python3 -m http.server 8000
```

重新生成数据（需要 Python 3 和 `pdftotext`）：

```bash
python3 pipeline/fetch.py                      # 巨潮公告元数据
python3 pipeline/fetch_prices.py 600187.SH     # 扶摇日 K 线，需要密钥
python3 pipeline/fetch_news.py 600187.SH       # 扶摇新闻和异动解读，需要密钥
python3 pipeline/build_events.py               # 组装并校验，生成 data/events.json
python3 pipeline/check_compliance.py           # 合规词检查
```

环境变量（放在本地 `.env`，不入库）：

| 变量 | 用途 |
|---|---|
| `FUYAO_API_KEY` | 扶摇金融数据 API |

## 已知边界

- 事件是挑出来的样例，不是全市场自动发现。
- 披露时间：巨潮只给到"日"，公告实际是前一晚上网的；媒体时间精确到分钟。页面上两者都显示并注明精度。
- 更新时间：两个数据源都不提供"事后修改时间"，目前一律显示"来源未提供"。
- 新闻证据用的是接口返回的标题和摘要，没有读全文。
- 行情只陈列事实，不做归因；"异动解读"的归因被标为推测。
- 已退市股票（如 605081）扶摇接口返回"代码不存在"，这类事件的行情栏会显示不可用。
- 传闻类证据目前没有真实样例。
