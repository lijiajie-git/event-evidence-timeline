# 前端参考与设计方向

2026-11-11。GitHub 搜索和读页面共用了 12 次（上限 25）。许可证和最近推送日期都是用 GitHub API 当天查的。

## 一、数据长什么样（前端要用到的部分）

`data/events.json` 顶层：`generated_at`、`disclaimer`、`events[]`。每个事件：

| 字段 | 前端怎么用 |
|---|---|
| `code` `name` `type` `period` `title` | 事件头。关注列表按 `code` 分组 |
| `merge_reason` | 标题下一行"为什么算同一个事件" |
| `evidence[]` | 证据时间线。每条有 `kind`（事实/观点/推测/传闻）、`source_tier`、`relation`（首次披露/更正，指向被更正的那条）、`times`（发生、披露、落款、抓取、更新）、`url`、`reason` + `reason_quote` |
| `claims[].versions[]` | 每个指标的各版数字：`low`/`high`、`quote`、`valid_from`/`valid_to`、`status`（active/superseded）。回放就靠 `valid_from`/`valid_to` 算"某天哪一版有效" |
| `conflicts[]` | 证据冲突：说明、两边原文、`resolution`（明确写了"这是推断"） |
| `pending[]` | 没并入、没接入的东西，要明说 |
| `status` `status_since` `notifications[]` | 状态和变化通知 |

回放的算法不需要新字段：截至 D 日，只显示 `disclosed ≤ D` 的证据；每个指标取 `valid_from ≤ D < valid_to` 的那一版；冲突的两边证据都已披露才显示。

**想请主窗口补的字段**（不改也能做，缺的会显示"未抽取"）：

1. 证据一句话要点 `summary`：e1 现在没有 `reason`，时间线上只能显示标题。
2. `times.updated` 为 `null` 是什么意思：没更新过，还是没记录？现在先显示"未记录"。
3. 冲突的 `resolution` 加一个 `resolution_kind: "推断"`，前端就不用从文案里猜。
4. 关注标的列表：现在从事件里的 `code` 推出来。如果要演示"关注了但还没有事件"的股票，需要一个 `watchlist[]`。

**字体加载的一个坑**：评审大概率在国内打开。Google Fonts 在国内不可用，所以字体走 jsDelivr 上的 fontsource 切片包，失败时回落到系统字体（苹方、宋体），页面不会因为字体加载失败而变样太多。

**颜色的一个坑**：A 股红涨绿跌。任何红色、绿色都会被读成"利好/利空"，这和"不出涨跌判断"冲突。三个方向都不用红绿表达状态：现行版本用靛蓝或青色，冲突用赭黄。

**没找到能直接用的现成组件**：时间线组件（react-chrono、TimelineJS）都是"一条竖线 + 圆点 + 卡片"的讲故事样式，表达不了"同一个数字有三版、各自在哪段时间有效"。所以三个方向都是手写 HTML/SVG，不依赖 UI 框架。

## 三、三个设计方向

小样都在本目录，双击就能在浏览器里打开（数据是 `mock-data.js` 里的 `events.json` 快照，正式版会改成运行时读取 `data/events.json`）。每个小样右上角能切浅色/深色，"截至"回放都能实际操作。

### 方向 A：公告纸（编辑排版）——`A-公告纸.html`

- **参考**：tufte-css（边注）、evidence（文字和数字放一起）、Observable Plot 的区间点线图。
- **字体**：标题和导语用思源宋体（Noto Serif SC），界面文字用系统黑体（苹方），数字用表格等宽数字（`tabular-nums`）。
- **配色**：米白纸色底、墨色字、一个靛蓝（现行版本）、一个赭黄（冲突）。深色是暖黑底。
- **分区**：左边窄栏是关注标的和变化通知；中间一栏像一篇报道：事件头 → 归并依据 → "截至"刻度尺 → 一段现状导语 → 冲突 → 每个指标的数轴 → 证据逐条；原文引用放在正文右边的页边。
- **被更正的说法**：每个指标一条数轴，三版区间画在同一根轴上、上下错开，旧版淡墨、现行版实心靛蓝；0 位置画一条竖线，扣非净利润从轴右边跳到左边，一眼看出"由盈转亏"。
- **回放**：事件头下面一条刻度尺，每次披露一个刻度，拖动或点刻度切换"截至"日期；导语、数轴、证据跟着变，没披露的版本直接不画。
- **技术栈**：纯 HTML + CSS + 原生 JS（ES module），手写 SVG，无构建步骤；GitHub Pages 直接托管。

### 方向 B：研究终端（高密度表格）——`B-研究终端.html`

- **参考**：Blueprint / Carbon 的紧凑表格、webtui 的终端克制感、OpenBB 的分栏；"前值 / 修正值"借财经日历的列结构。
- **字体**：IBM Plex Sans + IBM Plex Mono（数字、日期、公告号全部等宽），中文落到系统黑体。
- **配色**：深色优先，石墨灰底、浅灰字；现行版本用青色细边，冲突用琥珀色。浅色主题是冷白底。
- **分区**：顶部一行状态条（标的 / 事件 / 状态 / 截至）；左栏关注表和通知日志；中间是证据表，点一行展开原文；下面是"口径对照"表；右栏是当前结论、冲突、未接入。
- **被更正的说法**：口径对照表，一行一个指标，列是"首次 1-30 / 更正 4-18 / 更正 4-29（现行）/ 变化"。旧版数字灰色，下面一行小字"被临 2026-014 取代"；现行格子左侧一道青色线、底色略深；"变化"列写最近一次是"下调"还是"上调"，和首次相比正负号翻了的另起一行写"较首次由盈转亏"。
- **回放**：状态条里的"截至"可以用 ← → 键或两个按钮在披露日之间跳；表格里晚于截至日的列显示"尚未披露"。
- **技术栈**：同 A，纯静态。

### 方向 C：有效期泳道（时间为主角）——`C-有效期泳道.html`

- **参考**：vis-timeline 的"条段 + 当前时刻线"，Observable Plot 的分面。
- **字体**：Inter（数字和西文，开等宽数字）+ 系统黑体，不用衬线。
- **配色**：冷白底、近黑字、深青色（现行）、浅青灰（已被取代）、赭黄（冲突）。
- **分区**：顶部标签条切换关注标的；下面整宽一张泳道图：第一道是公告（每次披露一个标记），后面每个指标一道，每一版数字是一段横条，从生效日画到被取代那天；一根竖线是"截至"。图下面左边是证据列表，右边是截至那天的结论卡。
- **被更正的说法**：横条本身就是答案——旧版的横条在被取代那天截断、颜色变浅，条上写着当时的数字；现行版一直延伸到今天。看的是"哪段时间市场看到的是哪个数"。
- **回放**：在图上任意位置点击或拖动竖线；结论卡写"截至 X，有效的是 Y 版"。
- **技术栈**：同 A，纯静态。

## 四、（已作废）推荐：A 为主，把 B 的口径对照表收进来

**推荐 A（公告纸）**，理由：

1. **最不像 AI 生成的页面。** 宋体标题、米白纸色、细线分隔、引用放页边，是报纸和研报的排版语言；没有卡片、没有徽章、没有渐变。
2. **"数字往哪边漂"一眼能看到。** 同一根数轴上三版区间上下错开，扣非净利润从 0 右边跳到左边，不用读数字就知道"由盈转亏"。B 要读表格才看得出来，C 的横条长度表达的是时间，不是数值。
3. **后面的事件不一定有数字。** 主窗口要加的科达制造重组终止、港股传闻澄清，主要是状态变化（筹划 → 终止，传闻 → 否认），没有 `claims`。A 的骨架是"导语 + 证据逐条"，数轴那一节没有数据就整节不出现，页面照样完整；C 的泳道图在没有数字的事件上只剩一条公告道，主视觉就空了。
4. **适合两类用户。** 个人投资者从上往下读导语就够；投顾助理需要抄数，所以把 B 的"口径对照"表作为数轴下面的一个切换（"数轴 / 表格"），表格里是万元原值、等宽数字，方便复制。

**不选 B 作主方向**：信息最全、最像专业工具，但第一眼是一堆表格，"现在是什么状态"需要用户自己去右栏找；深色终端风也容易被理解成在模仿某家行情软件。

**不选 C 作主方向**：回放体验最好（任意一天、拖动连续），但 4-18 那一版只有效 11 天，在真实时间轴上只有几十像素宽，数字只能挤到条外；手机上整张图要横向滚动。C 的"拖动到任意一天"可以借到 A 里：A 的刻度尺现在只停在披露日，可以改成允许停在任意一天。

## 五、小样里已知没处理好的地方（正式版要改）

- A 在手机宽度下，数轴底部的刻度数字在区间很近时会挤在一起；值列的长区间（`−3,600 ~ −2,900 万`）会折行。正式版在窄屏把数值放到横条上方。
- B 在手机上表格靠横向滚动，没做卡片化。
- C 的泳道图最小宽度 640px，手机上横向滚动。
- 三个小样都只有 1 个事件，左栏切换事件、`pending` 以外的缺字段情况（比如整个 `claims` 缺失）还没演示到；正式版会做一份字段缺失的测试数据（只放在前端测试目录，不进 `data/`）。
- 字体从 jsDelivr 加载，国内网络下的实际速度没测。

## 六、本人否掉 A/B/C 之后的做法（2026-11-11，现在线上用的）

本人看过三个小样后觉得都不行，给的参考是自己之前做的校园跑腿作品（舞台上放设备，旁边讲解，底部步骤条自动播放）。照这个思路改成：

- **演示页（`index.html`）是一个舞台。** 左边一台横放的 iPad，里面跑的就是工作台本身（`workbench.html?embed`，同一份代码，不是截图）；右边是"后台做了什么"：把离线处理的过程按步骤回放（抓取、模型抽取、逐字校验、关联版本、冲突处理、问答 trace）。底部是 8 段步骤条：总览、消息会过期、转述对不上、前提会失效、状态说粗了、摘要能核对、查一句话、自己试。打开就自动播放，约 1 分 15 秒；在 iPad 里点任何地方就停下来交给人。
- **每段的例子都从数据里挑**，不写死事件编号：比如"消息会过期"选版本最多的指标，"转述对不上"选来源级别混合、优先数字口径的冲突，"前提会失效"选第一条有 `outdated_by` 的观点。主窗口加新事件后，演示会跟着变。
- **工作台（`workbench.html`）**：事件 / 问答 / 消息查验三个视图。事件页从上到下是：归并依据、"截至"回放（拖动到任意一天，← → 跳披露日）、分时点结论（事实 / 推断 / 还不确定，每句挂证据编号，点编号弹出原文）、证据冲突、数字版本（数轴和表格两种看法，作废的版本用虚线框）、证据时间线（按来源级别筛选，观点前提失效会标出来）、披露前后股价、还没做到。
- **配色**：外层沿用夜蓝 + 琥珀（本人对校园跑腿那套的认可），iPad 屏幕里是浅色产品界面；两边都有深色。不用红绿表达任何状态。只用系统字体，不加载外部字体（国内打不开 Google Fonts，jsDelivr 也不稳）。
- **技术**：纯静态，原生 ES module，没有构建步骤和依赖；GitHub Pages 继续从 main 根目录发布，线上地址不变。代码在 `web/`：`core.js`（读文件兜底、回放、格式）、`verify.js`（消息查验）、`app.js` + `app.css`（工作台）、`stage.js` + `stage.css`（演示页）。
- **缺数据时**：`events.json` 读不到，两个页面都显示明确的错误，不显示任何结论；`qa.json`、`audit.json`、`eval/report.json` 缺失时对应位置写"未生成"和文件路径；事件里缺字段的地方写"未抽取""未接入""来源未提供"。

### 第二轮加的三项（来自同类产品的启发）

- **点引用看原文**：数字版本的每一行、证据里的引用、冲突里的引用都能点开，右侧抽屉读 `data/raw/text/<ref>.txt`，按标点把 PDF 断行接回段落，两边去掉空白（全角逗号当半角，和组装脚本的校验口径一致）后逐字匹配，黄色底标出原句并滚动到位。找不到就写“未能在正文中定位”，保留巨潮 PDF 链接。新闻没有全文，只显示标题、摘要和链接。
- **两版公告对比**：先把完全相同的句子计数，其余句子按相似度两两配对（更正公告会把旧数字挪到“更正前”一段，所以不按顺序配），再按“词”比较，整个数字算一个单位。左旧右新，只给改动加底色，不用删除线；手机上改成上下两行。
- **结论修订记录**：结论卡右上角“修订记录 · N 版”，列出每一版的日期、因为哪份公告、事实/推断/不确定各几句，点开看当时全文，可以一键回放到那天。回放时只列出截至当天的版本。
- 状态轨按 `status_history[].code` 画形状（进行中空心圆、兑现实心圆、未通过和终止审核菱形、终止和否认实心方块），文字用 `status`。数字版本旁边注明 `raw` 的原文口径。
